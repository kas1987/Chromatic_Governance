# Product Family

Product-family keeps agent work connected to user value, scope discipline, requirements clarity, and roadmap logic.

## Implemented skills

| Skill | Purpose |
|---|---|
| `user-story` | Convert rough product intent into testable user stories. |
| `requirements` | Produce functional and non-functional requirements. |
| `scope-cut` | Reduce bloated plans into smaller shippable scope. |
| `mvp-plan` | Define the smallest useful release that tests the product bet. |
| `prioritize` | Rank work by impact, effort, confidence, risk, and fit. |
| `roadmap` | Sequence work across milestones, themes, or horizons. |
| `ux-critique` | Review flows, mockups, and interactions for usability. |
| `feedback-loop` | Turn feedback signals into themes, backlog, and experiments. |

## Operating sequence

1. Use `feedback-loop` or `user-story` to capture raw product intent.
2. Use `requirements` to remove ambiguity.
3. Use `scope-cut` and `mvp-plan` to prevent overbuild.
4. Use `prioritize` and `roadmap` to sequence work.
5. Route ready work to architecture, security, QA/eval, docs, and release families.

## Guardrails

- Preserve evidence separately from interpretation.
- Mark assumptions and weak signals.
- Do not convert every request into a feature.
- Do not cut safety, privacy, accessibility, or release controls for speed.
- Prefer smaller, testable releases over broad speculative builds.
