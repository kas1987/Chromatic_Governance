# RPI Lifecycle Plugin

RPI is the delivery lifecycle plugin family for scoped work: discovery, planning, execution, testing, review, refactor, bug hunting, retrospectives, and handoff readiness.

## Skills

- `discovery` - clarify ambiguous work before planning or implementation.
- `plan` - create phased execution plans with validation gates.
- `crank` - drive steady execution through a known task list.
- `swarm` - coordinate parallel agents or workstreams.
- `implement` - apply scoped changes after requirements are clear.
- `council` - run multi-perspective tradeoff review.
- `quick-execute` - complete small, low-risk work fast.
- `vibe` - define creative/tone/experience direction.
- `validation` - verify acceptance criteria and readiness.
- `pre-mortem` - identify likely failure modes before work.
- `post-mortem` - capture lessons and corrective actions after work.
- `test` - design or run checks for behavior and regressions.
- `review` - assess quality, risk, and approval readiness.
- `refactor` - improve structure without intended behavior changes.
- `bug-hunt` - reproduce, diagnose, and propose fixes.
- `handoff-ready` - package continuation state for another operator.

## Operating stance

Use RPI when the dominant need is delivery execution. Escalate to the specialized families when security, architecture, QA/evals, release, context, docs, product, observability, frontend, or governance concerns become the primary risk.
